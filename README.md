# Click Trader

**진입은 직접, 청산은 규칙대로.** 한국투자증권 Open API를 사용하는 로컬 퍼스트 웹 트레이딩 PoC입니다. React + TypeScript 정적 앱이며, AI 호출 없이 주문·청산 로직이 실행됩니다.

## 실행

Node.js 22.12 이상을 권장합니다.

```sh
npm ci
npm run dev
```

<http://localhost:5197>에서 확인합니다. 다른 기기에서 개발 서버를 공개 접근하도록 운영하지 마세요. 로컬 개발 릴레이는 사용자의 키와 주문을 KIS로 전달합니다.

```sh
npm test
npm run build
npm run preview
```

`dist/`를 정적 호스팅에 배포할 수 있습니다. 포함된 GitHub Actions 워크플로는 테스트·빌드 후 GitHub Pages에 배포합니다. 저장소 Settings → Pages의 Source는 GitHub Actions로 설정합니다.

## 두 가지 실행 경로

| 경로 | 시세 | 주문 | 용도 |
|---|---|---|---|
| 내장 데모 | 명확하게 표시한 합성 호가, 타이머 갱신 | 가상 체결 | 정적 페이지에서 전체 UX·엔진 검증 |
| KIS 연결 | KIS WebSocket 체결·10호가 | 실제 REST 주문·정정 | 로컬 개발 릴레이로 통신 검증 가능 |

**정적 호스팅만으로 KIS 실거래가 가능하다고 검증된 상태는 아닙니다.** 2026-11-02, 인증정보 없는 CORS 사전 요청 확인에서 토큰 발급 및 주문 엔드포인트의 `OPTIONS` 응답이 `501`이고 CORS 허용 헤더가 없었습니다. 공식 레퍼런스의 WebSocket 주소는 `ws://ops.koreainvestment.com:21000`이며 HTTPS 페이지에서는 혼합 콘텐츠 제한도 있습니다.

앱에는 직접 연결 어댑터를 구현했지만, 브라우저가 차단하면 원인을 표시합니다. Vite의 **개발 전용 고정 목적지 릴레이**는 REST와 WebSocket을 같은 로컬 출처로 연결합니다. 릴레이는 `dist/`에 포함되지 않으며, `npm run preview`에도 없습니다. GitHub Pages에서 릴레이를 선택해도 작동하지 않습니다. 서버 없는 실거래를 완료하려면 증권사 측 브라우저 지원 또는 별도 전송 계층이 필요합니다.

KIS 모의계좌의 정정가능조회 지원은 확인되지 않아 이 버전은 모의계좌 거래 연결을 차단합니다. 내장 데모와 KIS 모의투자는 서로 다릅니다. 실제 계좌 자동 청산은 API 어댑터를 구현한 단계이며, 실주문 검증은 수행하지 않았습니다.

## 사용 순서

1. **데모 → 연결 시작**으로 호가와 거래 흐름을 확인합니다.
2. 종목·수량·익절·손절을 설정하고 **매수**를 누릅니다.
3. 매수 체결 수량마다 익절 지정가 매도를 등록합니다.
4. 데모의 상승·하락 버튼으로 익절 체결과 손절 정정을 확인합니다.
5. 실계좌 연동 시 **키 입력** 팝오버에서 App Key, App Secret, 계좌 앞 8자리, 상품코드, HTS ID, 환경을 입력합니다. 로컬 실행에서는 연결 방식을 개발 릴레이로 선택합니다.
6. 저장 암호로 잠금을 해제한 다음 KIS 모드에서 연결합니다. 키 저장만으로 주문하지 않습니다.

키 값은 저장소·빌드·로그에 넣지 않습니다. 예제 키도 포함하지 않습니다. 앱은 입력한 사용자 계좌를 사용합니다.

## 구현한 기능

- 반응형 3열 데스크톱 / 세로형 모바일 거래 화면
- 네이티브 Popover 키 입력, 암호 저장·잠금 해제·삭제
- 종목 선택 및 국내주식 6자리 코드 직접 입력, KRX 기준
- 매수·매도 10호가, 잔량 깊이 막대, 총 잔량, 스프레드
- WebSocket `H0STASP0`, `H0STCNT0`, 암호화 계좌 체결통보 `H0STCNI0`
- 1주·지정 수량 최유리 지정가 매수 (`ORD_DVSN=03`)
- 체결가 기준 금액 / 비율 익절·손절; 금액은 **1주당 가격 차이**
- 익절 일반 지정가 자동 등록, 손절 시 정정가능조회 후 기존 매도 잔량 가격 정정
- 손절 정정 가격: 최우선 매수호가보다 약 0.5% 낮은 유효 호가; 미체결 중 호가가 정정가 아래로 내려가면 2초 간격 제한으로 재정정
- 추가 매수는 독립된 체결 묶음으로 관리, 부분 체결 수량부터 익절 등록
- 누적 체결량 기준 중복 체결 제거, 주문 접수·체결 분리
- 명확한 주문 거절과 응답 불명확 구분; 불명확 주문 자동 재전송 금지
- 계좌별 주문번호·원주문 관계 추적, 이벤트 작업 직렬화
- 3초 주기 체결 대조 + 실시간 계좌 체결통보 수신 시 대조
- 실계좌 재접속 시 저장된 미종결 세션 복원, 주문 체결·해당 종목 잔고 대조
- 세션 누적 순실현손익 계단형 차트, 비용 전 평가손익, 체결 기록·JSON 내보내기
- 수수료·매도 세금 추정률 설정 (사용자 계좌에 맞게 변경)
- Web Locks로 같은 브라우저 출처의 중복 거래 탭 차단
- 포지션·미종결 주문 존재 시 `beforeunload` 경고
- 명시적 거래 종료 화면, 보유 수량 청산 및 체결 확인

## 청산 방식

```text
매수 접수 → 누적 체결 확인 → 체결 묶음 생성 → 익절 매도 지정가 등록
                                               ├─ 익절 체결 → 손익 기록
                                               └─ 매수 1호가가 손절 기준 이하
                                                    → 기존 매도 체결량 재확인
                                                    → 정정가능 수량 조회
                                                    → 미체결 잔량 가격 정정
                                                    → 구주문 경합 체결 반영
                                                    → 새 주문번호 체결 확인
```

목표가는 유효 호가 단위로 올림합니다. 익절·손절은 수수료 전 가격 기준이며, 차트만 입력한 비용 추정치를 차감합니다. 손절 지정가는 체결 가격이나 체결 자체를 보장하지 않습니다. 단일 계좌·단일 활성 종목을 관리하며 다른 종목으로 바꾸기 전 기존 거래를 종결해야 합니다.

## 저장과 복구

| 위치 | 데이터 |
|---|---|
| Local Storage | 선택 종목, 기본 수량, 다음 매수의 청산 규칙·비용률 |
| IndexedDB `vault` | PBKDF2-SHA256 310,000회 + AES-GCM으로 암호화한 계좌 인증정보 |
| IndexedDB `tokens` | 계좌 자격증명으로 암호화한 토큰·발급 시각, 계정 식별자는 해시 |
| IndexedDB `sessions` | 주문 의도·주문번호·체결 묶음·손익·이벤트 기록 |
| 메모리 | 잠금 해제된 키, 실시간 호가, 실행 중 상태 |

토큰은 24시간 이내 재사용하며 만료 직전 1분은 제외합니다. 저장 암호는 보관하지 않습니다. 잠금 해제된 실행 중 페이지의 스크립트는 키를 사용할 수 있으므로 IndexedDB 암호화를 실행 중 코드의 보안 격리로 해석하지 않습니다. 외부 분석 스크립트·CDN은 사용하지 않습니다.

주문 의도는 네트워크 전송 전에 기록합니다. 응답이 불명확하거나 저장 중 프로세스가 종료되면 자동으로 주문을 반복하지 않습니다. 주문번호 없는 거래는 HTS 대조가 필요하며 이 버전에는 임의로 상태를 초기화하는 기능을 두지 않았습니다.

## PoC 범위

- 자동 청산은 **브라우저가 실행 중이고 통신 가능한 동안** 작동합니다. 탭 종료·절전·강제 종료 후의 손절은 보장되지 않습니다. Service Worker나 `beforeunload`로 이를 보완했다고 주장하지 않습니다.
- 종료 시점에 주문을 전송하지 않습니다. 화면 내 청산 절차를 사용합니다. 미체결 매수와 불명확 주문은 HTS에서 확인·취소해야 합니다.
- 기존 계좌 보유분과 외부에서 실행한 거래는 자동 관리에 편입하지 않습니다. 전체 계좌 손익이 아니라 **이번 세션에서 확인한 매도 체결의 손익**입니다.
- 날짜를 넘긴 미종결 세션·많은 보유 종목으로 잔고 연속조회가 필요한 계좌는 수동 대조가 필요합니다.
- 동일 출처의 탭은 잠그지만 다른 기기·다른 출처·HTS와의 동시 주문을 통제하지는 못합니다.
- 공개 릴레이·사용자 인증 서버·Docker 배포는 포함하지 않습니다. API 이용 한도·장중 대량 체결·실계좌 정정 수명주기 검증은 후속 과제입니다.

## 패키지 선택

| 패키지 | 역할·선정 이유 |
|---|---|
| React + TypeScript | 컴포넌트 UI, 거래 상태·설정의 정적 타입 |
| Vite | 정적 빌드, 로컬 개발 서버와 개발 전용 프록시 |
| Recharts | React 기반 반응형 계단형 실현손익 그래프 |
| Lucide React | 개별 import 가능한 일관된 아이콘 |
| idb | IndexedDB 비동기 트랜잭션 접근 |
| Zod | 계좌 입력·청산 설정 런타임 검증 |
| Vitest | 부분 체결·중복 처리·익절/손절 경합 테스트 |

버전은 `package-lock.json`에 고정합니다. Popover·Dialog·Web Locks·Web Crypto는 브라우저 기본 API를 사용합니다. 과도한 전역 상태·UI 프레임워크는 추가하지 않았습니다.

