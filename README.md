# Click Trader

**진입은 직접, 청산은 규칙대로.** 한국투자증권 Open API를 사용하는 로컬 퍼스트 React + TypeScript 웹 트레이딩 PoC입니다. AI 호출 없이 주문·청산 로직이 실행됩니다.

## 시작 순서

1. 최초 접속 시 **계좌 키 입력 창만** 표시합니다. 거래 화면은 렌더링하지 않습니다.
2. App Key, App Secret, 계좌 앞 8자리, 상품코드, HTS ID, 환경과 연결 방식을 입력하고 저장 암호를 설정합니다.
3. 저장된 키가 있으면 새로고침 후 **암호로 잠금 해제**해야 합니다. 저장 암호는 보관하지 않습니다.
4. 종목을 선택한 적이 없으면 **종목 선택 창을 반드시 완료**해야 합니다. 삼성전자 등 특정 종목을 기본 선택하지 않습니다. 종목명 검색과 국내주식 6자리 코드 입력을 지원합니다.
5. 키와 종목이 준비된 뒤 거래 화면이 열립니다. **KIS 연결 시작**을 눌러 실제 시세를 연결합니다.
6. 연결 전·실패·연결 종료 상태에는 가격·잔량을 표시하지 않고 매수 버튼을 비활성화합니다.

**합성 호가·가상 체결·데모 모드는 제공하지 않습니다.** 과거 버전의 데모 장부는 실계좌 세션으로 불러오지 않으며, 과거의 자동 기본 종목 설정도 명시적인 사용자 선택으로 간주하지 않습니다. 차트는 실제 매도 체결이 확인된 이후 표시합니다.

## 로컬 실행

Node.js 22.12 이상을 권장합니다.

```sh
npm ci
npm run dev
```

<http://localhost:5197>에서 확인합니다. 개발 릴레이는 사용자 키와 주문을 KIS로 전달하므로 개발 서버를 외부에 공개해서 운영하지 마세요.

```sh
npm test
npm run build
npm run preview
```

`dist/`는 정적 호스팅에 배포할 수 있습니다. GitHub Actions에서 테스트·빌드 후 GitHub Pages에 배포하며, Pages Source는 GitHub Actions로 설정합니다.

## 브라우저 직접 연결의 현재 제약

**정적 호스팅만으로 KIS 실거래가 가능하다고 검증된 상태는 아닙니다.** 2026-11-02 인증정보 없는 CORS 사전 요청 확인에서 토큰 발급·주문 엔드포인트의 `OPTIONS`가 `501`을 반환했고 CORS 허용 헤더가 없었습니다. 공식 레퍼런스의 WebSocket 주소 `ws://ops.koreainvestment.com:21000`에는 HTTPS 페이지의 혼합 콘텐츠 제한도 있습니다.

직접 연결 어댑터는 연결 실패 원인을 화면에 표시합니다. 실패 시 대체 시세나 가상 주문으로 전환하지 않습니다. Vite의 **개발 전용 고정 목적지 릴레이**는 REST와 WebSocket을 로컬 동일 출처로 연결합니다. 릴레이는 `npm run dev`에서만 제공되며 `dist/`, GitHub Pages, `npm run preview`에는 없습니다.

KIS 모의계좌의 정정가능조회 지원은 미검증이므로 현재 버전은 모의계좌 거래 연결을 차단합니다. 실계좌 주문·자동 청산은 API 어댑터 구현 단계이며 실주문 검증은 수행하지 않았습니다. 저장소·빌드·로그에 사용자 인증정보를 포함하지 않습니다.

## 거래 기능

- 반응형 데스크톱 3열 / 모바일 세로 화면
- 필수 키 입력·잠금 해제, 필수 종목 선택, 거래 화면 내 키 수정 팝오버
- KRX WebSocket 체결가 `H0STCNT0`, 10호가 `H0STASP0`, 암호화 계좌 체결통보 `H0STCNI0`
- 매수·매도 잔량 깊이 막대, 총 잔량, 스프레드, 시세 지연 표시
- 1주·지정 수량 최유리 지정가 매수 (`ORD_DVSN=03`)
- 실제 체결가 기준 금액 / 비율 익절·손절; 금액은 **1주당 가격 차이**
- 체결 수량별 익절 지정가 등록, 손절 시 정정가능조회 후 기존 매도 잔량 가격 정정
- 손절 정정 가격은 최우선 매수호가보다 약 0.5% 낮은 유효 호가. 호가가 정정가 아래로 추가 하락하면 2초 간격 제한으로 재정정
- 추가 매수의 체결 묶음별 관리, 부분 체결 수량부터 익절 등록
- 주문 접수와 실제 체결 분리, 누적 체결량 중복 제거, 불명확 주문 자동 재전송 금지
- 주문번호·원주문 관계 추적과 이벤트 작업 직렬화
- 실시간 계좌 체결통보 및 3초 주기 조회를 통한 체결 대조
- 저장된 실계좌 미종결 세션 복원과 해당 종목 잔고 대조
- 세션 순실현손익 계단형 차트, 비용 전 평가손익, 거래 JSON 내보내기
- 사용자 수수료·세금 추정률 설정; 차트는 계좌 전체 손익이 아닌 해당 세션 기준
- Web Locks 단일 거래 탭, 보유·미종결 주문의 `beforeunload` 경고, 명시적 청산·종료 절차

## 주문 흐름

```text
매수 접수 → 실제 체결 확인 → 익절 매도 지정가 등록
                                ├─ 익절 체결 → 손익 기록
                                └─ 매수 1호가가 손절 기준 이하
                                     → 기존 매도 체결량 확인
                                     → 정정가능 수량 조회
                                     → 미체결 잔량 가격 정정
                                     → 구주문 경합 체결 반영
                                     → 새 주문번호 체결 확인
```

목표가는 유효 호가 단위로 올림합니다. 익절·손절은 수수료 전 가격 기준이며, 차트는 입력한 비용 추정치를 차감합니다. 손절 지정가는 체결 가격이나 체결 자체를 보장하지 않습니다. 다른 종목을 선택하려면 기존 거래를 먼저 종결해야 합니다.

## 저장과 복구

| 위치 | 데이터 |
|---|---|
| Local Storage | 사용자가 명시적으로 선택한 종목, 기본 수량, 청산 규칙·비용률 |
| IndexedDB `vault` | PBKDF2-SHA256 310,000회 + AES-GCM으로 암호화한 계좌 인증정보 |
| IndexedDB `tokens` | 계좌 자격증명으로 암호화한 토큰·발급 시각; 식별자는 해시 |
| IndexedDB `sessions` | 주문 의도·주문번호·체결 묶음·손익·이벤트 |
| 메모리 | 잠금 해제된 키, 실제 수신한 호가, 실행 상태 |

토큰은 24시간 이내 재사용하며 만료 직전 1분은 제외합니다. 잠금 해제된 페이지의 코드는 키를 사용할 수 있으므로 IndexedDB 암호화가 실행 중 코드까지 격리하는 것은 아닙니다. 외부 분석 스크립트·CDN은 사용하지 않습니다.

주문 의도는 전송 전에 기록합니다. 주문번호 없는 불명확 거래는 HTS 대조가 필요하며 임의로 상태를 초기화하거나 자동 재주문하지 않습니다.

## 실행 범위

자동 청산은 브라우저가 실행 중이고 통신 가능한 동안 동작합니다. 탭 종료·절전·강제 종료 후 손절은 보장되지 않으며 종료 순간에 주문을 전송하지 않습니다. 미체결 매수와 불명확 주문은 HTS에서 확인·취소해야 합니다.

기존 보유분·외부 거래는 자동 편입하지 않습니다. 날짜를 넘긴 미종결 세션과 잔고 연속조회가 필요한 계좌는 수동 대조가 필요합니다. 동일 출처의 탭만 잠그며 다른 기기·다른 출처·HTS와의 동시 주문은 통제하지 않습니다.

## 구성

React + TypeScript, Vite, Recharts, Lucide React, idb, Zod, Vitest를 사용합니다. 버전은 `package-lock.json`에 고정합니다.

```text
src/App.tsx              거래 화면, 연결·세션 제어
src/Setup.tsx            필수 키 입력·잠금 해제 및 종목 선택
src/engine.ts            주문 의도와 체결·청산 상태 전이
src/kis.ts               KIS REST·WebSocket·체결통보
src/storage.ts           암호화 키, 토큰 캐시, 장부·설정
src/model.ts             도메인 타입·호가 단위·입력 스키마
src/PerformanceChart.tsx 실제 세션 실현손익 그래프
src/engine.test.ts       부분 체결·주문 경합·중복 처리 검증
```

참고: [KIS 공식 예제](https://github.com/koreainvestment/open-trading-api), [Recharts](https://recharts.github.io/en-US/guide/installation/), [idb](https://github.com/jakearchibald/idb), [Lucide](https://lucide.dev/guide/packages/lucide-react), [Zod](https://zod.dev/).
