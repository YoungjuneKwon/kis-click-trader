# Click Trader

**진입은 직접, 청산은 규칙대로.** React + TypeScript 프론트엔드와 로컬 Node.js 인증·KIS 중계 서버로 구성한 트레이딩 PoC입니다. AI 호출 없이 실행합니다.

## 실행

Node.js 22.12 이상을 권장합니다. `.env.example`을 참고해 서버 환경변수를 설정합니다. 실제 `.env`는 커밋하지 않습니다.

```sh
npm ci
npm run serve
```

`npm run serve`는 프론트엔드와 서버를 빌드한 뒤 <http://127.0.0.1:5197>에 서버를 띄웁니다. 이미 빌드했다면 `npm start`를 사용합니다.

외부 파일을 사용하려면 경로만 지정합니다. 파일 내용은 서버 프로세스에서 읽으며 프론트엔드 빌드에 포함하지 않습니다.

```sh
KIS_ENV_FILE=/path/to/kis/.env npm run serve
```

## 서버 환경변수

| 변수 | 용도 |
|---|---|
| `KIS_API_KEY` | App Key |
| `KIS_API_SECRET` | App Secret |
| `KIS_CANO` | 계좌 앞 8자리 |
| `KIS_ACNT_PRDT_CD` | 상품코드 2자리 |
| `KIS_HTS_ID` | 선택: 실시간 계좌 체결통보 구독 |
| `KIS_ENV` | `prod` / `vps`, 기본 `prod` |
| `CT_PW` | 필수: 화면 잠금 인증 암호 |
| `KIS_ENV_FILE` | 사용할 `.env` 경로, 기본 프로젝트 `.env` |
| `KIS_TOKEN_STATE_PATH` | 토큰 캐시 경로, 기본 `/tmp/kis_access_token_state.json` |
| `HOST`, `PORT` | 기본 `127.0.0.1`, `5197` |

API 키·시크릿·계좌정보·HTS ID·화면 암호는 서버 환경변수에서만 읽습니다. `VITE_` 접두사를 사용하지 않습니다. 토큰·웹소켓 접속키·계좌 통보 복호화 키도 브라우저에 전달하지 않습니다.

HTS ID가 없어도 실제 호가 조회와 주문을 사용할 수 있습니다. 그 경우 내 주문의 체결 확인은 REST 3초 주기 조회로 수행합니다. HTS ID가 있으면 실시간 체결통보를 추가 구독하여 확인을 앞당깁니다. 구독 실패 시에도 호가는 유지하며 REST 조회를 사용합니다. 현재 확인 방식을 화면에 표시합니다.

## 화면 사용

1. 접속하면 화면 잠금 암호만 입력받습니다. 서버의 `CT_PW`로 인증합니다.
2. 종목이 설정되지 않았으면 종목 선택 창을 완료해야 합니다. 기본 종목은 없습니다.
3. **KIS 연결 시작**을 누르면 로컬 서버를 통해 실제 WebSocket 호가를 받습니다.
4. 수량·익절·손절을 설정한 뒤 매수합니다. 실제 체결 수량부터 익절 매도를 등록합니다.
   이미 진입한 건도 바꾸려면 값을 입력한 뒤 **익절·손절 적용**을 누릅니다. 입력 도중에는 기존 주문을 변경하지 않습니다.
5. 거래 종료 시 보유·미체결 상태를 확인합니다. 보유 수량이 없는 상태에서는 화면을 수동 잠글 수 있습니다.

### 진입건별 내역과 청산 범위

‘이 화면의 진입 내역’은 **매수 주문 1건당 하나의 행**을 표시합니다. 한 주문이 나뉘어 체결돼도 같은 진입건 아래 합산합니다. 각 행에는 주문 수량·체결 수량·미체결·미청산 수량, 평균 진입가·청산가, 자체 실현·미실현손익과 즉시 청산 버튼이 있습니다.

데스크톱에서는 매수 패널 옆 열의 축소된 손익 카드 아래에 진입 내역을 배치합니다. 미종결 진입건을 먼저 표시하고 종료된 진입·상세 체결 기록은 접어 둡니다. 모바일에서는 매수 영역 다음에 손익·진입 내역을 표시합니다.

즉시 청산은 해당 진입건의 미체결 매수 주문만 취소하고, 그 진입건의 매수 체결에 연결된 익절 매도 주문 잔량만 정정합니다. 취소와 경합하여 추가 체결된 물량도 같은 진입건에 기록해 청산합니다. 중복 클릭은 주문 중복 전송으로 이어지지 않습니다. ‘이 화면 거래분 전체 청산’도 이 장부의 진입건만 순회합니다.

기존 계좌 보유분은 편입하지 않습니다. 계좌 잔고는 수량 대조와 관리 대상 외 보유분 안내에만 사용하며 **KIS 계좌 평균매입가·평가손익을 손익 계산에 사용하지 않습니다.** 손익은 진입건에 속한 주문별 체결금액에서 해당 매수 원가와 설정된 추정 비용을 차감합니다. 주문별 총체결금액이 있으면 반올림된 평균가보다 우선 사용합니다. 새로고침·재연결 시 같은 계좌의 당일 진입 장부를 합쳐 복원하며, 주문·체결 ID를 기준으로 중복 집계를 막습니다.

### 진입 후 익절·손절 변경

폼의 값은 다음 매수에 사용합니다. **익절·손절 적용**을 누르면 이 화면에서 관리 중인 미청산 진입건과 아직 체결되지 않은 해당 매수 잔량에도 새 규칙을 저장합니다. 기존 보유분·청산 완료 건·이미 청산 진행 중인 건은 제외합니다.

- 익절: 기존 매도 주문의 미체결 잔량만 실제 지정가 정정합니다. 가격이 같으면 재정정하지 않습니다.
- 손절: 진입건의 감시 기준을 갱신합니다. 새 기준에 현재 매수 1호가가 이미 도달했다면 손절 청산 조건을 즉시 확인합니다.
- 정정 중 원주문 체결을 대조하며, 접수된 새 주문번호를 먼저 저장합니다. 조회가 지연되면 저장된 번호로 대조를 이어가고 정정 주문을 다시 보내지 않습니다.
- 적용 결과와 각 진입건의 실제 익절 예약가·손절 감시가를 표시합니다. 일부 정정 실패는 실행 로그에 표시하며 성공으로 간주하지 않습니다.
- 기존 진입건의 수수료·세금 추정률은 변경하지 않습니다.

### 작은 호가창과 최근 시세 차트

호가창은 그레이스케일로 매도·매수 각 4단계, 총 8행을 표시합니다. WebSocket에서는 전체 10단계를 받으며 총잔량은 전체 호가 기준입니다.

호가창 아래에는 최근 30분의 실제 **1분봉 종가, 5MA, 10MA**를 표시합니다. `FHKST03010200` 분봉 조회를 최대 두 번 호출해 이동평균 계산용 앞 구간도 확보하고, 표시 구간만 최근 30분으로 자릅니다. 이후 실제 시장 체결 시각·가격으로 진행 중인 1분봉을 갱신하고 분봉을 주기적으로 대조합니다. 누락된 분봉을 임의로 채우지 않으며, 데이터가 부족하거나 연속되지 않으면 해당 이동평균을 표시하지 않습니다. 마지막 분봉은 아직 진행 중일 수 있습니다.

조회 실패 시 접속 후 실제로 확보한 구간만 표시한다는 안내를 제공합니다. 초기 시세 조회와 자동 청산은 독립적으로 동작합니다.

실제 데이터를 수신하기 전에는 가격·잔량을 표시하지 않고 매수를 비활성화합니다. 합성 호가·데모 주문은 제공하지 않습니다. 실현손익 차트는 실제 매도 체결 이후 표시합니다.

## 구성

```text
브라우저: React UI · 수동 매수 · 청산 규칙 · 거래 엔진
       │ 동일 출처 HTTP + WebSocket, HttpOnly 인증 쿠키
       ▼
Node.js / Fastify
  ├─ CT_PW 화면 인증, 세션 확인
  ├─ 빌드된 프론트엔드 제공
  ├─ KIS REST: 서버 키·계좌·토큰 주입, 주문 해시 생성
  └─ KIS WebSocket: 접속키 발급·구독·계좌통보 복호화
       │
       ▼
한국투자증권 Open API
```

이 서버가 KIS와 통신하므로 브라우저 직접 호출의 CORS 및 HTTPS→`ws://` 혼합 콘텐츠 문제를 피합니다. GitHub Pages는 프론트 정적 배포만 가능하며 이 백엔드를 실행하지 못합니다. 정적 호스팅에서는 백엔드가 없다는 안내를 표시하고 암호 입력·전송을 막습니다.

인증된 세션만 REST·WebSocket을 사용할 수 있습니다. 세션은 HttpOnly·SameSite=Strict 쿠키를 사용하며 기본 8시간 후 만료됩니다. 외부 출처 요청과 허용하지 않은 KIS 경로·거래 코드는 거절합니다. 서버 로그에 비밀번호·키·요청 본문을 출력하지 않습니다. 기본 바인딩은 로컬 루프백입니다.

## 주문과 청산

- KRX 10호가 `H0STASP0`, 시장 체결가 `H0STCNT0`
- 선택 실시간 계좌 체결통보 `H0STCNI0`는 서버에서 복호화하고 브라우저에는 변경 이벤트만 전달
- 1주·지정 수량 최유리 지정가 매수 (`ORD_DVSN=03`)
- 진입 주문별 즉시 청산, 해당 주문의 미체결 매수 취소, 진입건별 자체 손익
- 체결 묶음별 일반 지정가 익절 매도, 부분 체결 수량부터 보호
- 체결가 기준 금액 / 비율 익절·손절; 금액은 **1주당 가격 차이**
- 손절 시 기존 매도 체결량과 정정가능 수량을 조회한 뒤 미체결 잔량 가격 정정
- 정정 가격은 매수 1호가보다 약 0.5% 낮은 유효 호가. 추가 하락으로 미체결이면 2초 간격 제한으로 재정정
- 누적 체결량 중복 제거, 접수·체결 분리, 불명확 주문의 자동 재전송 금지
- 주문 의도 사전 기록, 재시작 시 실계좌 미종결 세션 및 해당 종목 잔고 대조
- 세션 순실현손익 차트·비용 전 평가손익·거래 내보내기

체결 확인과 익절 주문 등록에는 통신·서버 처리 시간 및 REST 조회 주기가 반영됩니다. 즉시 체결 인지나 특정 가격의 손절 체결을 보장하지 않습니다. KIS 모의계좌의 정정가능조회는 미검증이므로 현재 거래 연결은 실전 어댑터 기준입니다.

## 저장

| 위치 | 데이터 |
|---|---|
| 서버 환경변수 | API 인증정보, 계좌, HTS ID, 화면 암호 |
| 서버 메모리 | 인증 세션, 잠금 암호의 임시 검증 해시, 접근 토큰·웹소켓 접속키 |
| 서버 토큰 캐시 | 접근 토큰·발급 시각; 24시간 이내 재사용, 파일 권한 `0600` |
| Local Storage | 비밀값이 아닌 종목·수량·청산 규칙·비용률 |
| IndexedDB | 주문·체결·손익·이벤트 장부 |
| HttpOnly 쿠키 | 불투명 인증 세션 식별자 |

과거 버전의 IndexedDB `vault`·`tokens` 저장소는 시작 시 비워 브라우저에 인증정보를 남기지 않습니다. 기존 주문 장부는 유지합니다. API 키 입력·저장 UI는 제거했습니다.

## 동작 범위

현재 자동 청산 엔진은 브라우저에서 실행하며 Node 서버는 인증과 API 중계를 담당합니다. 탭 종료·절전·화면 잠금·세션 만료·통신 단절 시 자동 손절 감시는 중단됩니다. 실행 중 보유·미종결 주문은 종료 경고를 표시합니다. 미체결 매수·불명확 주문은 HTS에서 확인·취소해야 합니다.

기존 보유분·외부 거래는 자동 편입하지 않습니다. 날짜를 넘긴 미종결 세션이나 잔고 연속조회가 필요한 계좌는 수동 대조가 필요합니다. Web Locks는 같은 출처의 중복 거래 탭만 막으며 다른 기기·HTS 동시 주문은 통제하지 않습니다.

## 개발·검증

```sh
npm test
npm run build
npm audit --omit=dev
```

프론트 개발은 Node 서버를 먼저 띄운 뒤 `npm run dev`로 <http://127.0.0.1:5198>에서 진행합니다. `/api`는 로컬 Node 서버의 5197 포트로 연결됩니다. 프론트 개발 서버 자체에 KIS 비밀값을 주입하지 않습니다.

React·TypeScript·Recharts·Lucide·idb·Zod, Fastify·WebSocket·dotenv, Vitest를 사용하며 버전은 `package-lock.json`에 고정합니다. 토큰 재사용·서버 인증·자격증명 격리·부분 체결·정정 경합 등을 테스트합니다.

```text
server/index.ts          .env 로딩, 서버 실행
server/config.ts         서버 필수 설정 검증
server/app.ts            화면 인증, API 보호, 정적 파일 제공
server/kis-service.ts    서버 전용 KIS REST·WebSocket·토큰
src/App.tsx             거래 화면·세션·청산 엔진 연결
src/Setup.tsx           화면 잠금·종목 선택
src/api.ts              잠금 인증 클라이언트
src/kis.ts              로컬 중계 서버 클라이언트
src/engine.ts           주문·체결·청산 상태 전이
src/EntryHistory.tsx     진입 주문 1건 단위 내역·개별 청산
src/entry-summary.ts    진입건·이 화면 거래 범위의 자체 손익
src/IntradayChart.tsx   실제 최근 30분 종가·5MA·10MA
src/intraday.ts         분봉 병합·시간축·이동평균 계산
src/storage.ts          비밀값 없는 장부·UI 설정
```

참고: [KIS 공식 예제](https://github.com/koreainvestment/open-trading-api), [Fastify](https://fastify.dev/), [Recharts](https://recharts.github.io/), [idb](https://github.com/jakearchibald/idb).
